# ADR 006 — Runtime support and incremental infrastructure

**Status:** accepted for planning; owner approved JUnit 6 on 2026-10-21. Selected baseline: Java 21, Spring Boot 4.x, Maven, Spring Web, PostgreSQL, JPA/Hibernate, Flyway, Resilience4j, Kafka at M7, Boot-managed JUnit 6/Jupiter, Mockito, Testcontainers, k6, OTel/Micrometer/Prometheus/Grafana, later Compose/Actions/ECS/RDS.

Research found [Boot 3.5.16 ended OSS support](https://spring.io/blog/2026/06/25/spring-boot-3-5-16-available-now/); its [testing docs](https://docs.spring.io/spring-boot/3.5/reference/testing/index.html) use JUnit 5, while [current Boot testing](https://docs.spring.io/spring-boot/reference/testing/index.html) uses JUnit 6. The owner selected JUnit 6, resolving the earlier testing-generation question. Use Boot's dependency management instead of forcing independently mixed test versions. M1 will verify and pin compatible supported patches and integration-library versions.

No exact patch matrix is pinned and no build is generated now. Redis/Kubernetes/microservices/native images are deferred absent need. Compose/local correctness precedes CI/cloud; deployment and billable resources require later explicit approval. Verify dependency/resilience/telemetry compatibility at implementation rather than treating this planning decision as an executed compatibility test. This approval does not start milestone 1 or authorize application implementation.
